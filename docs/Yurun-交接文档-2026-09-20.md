## 1. 产品定义

语润不是系统输入法，也不替换用户现有的微软拼音、搜狗、Rime 等输入法。

当前产品定位是：

> Windows 全局语音输入层

主路径：

```text
光标放好 → 按住热键 → 说话 → 松开 → 文字进入原输入框
```

产品优先级：

1. `Direct / 快速输入` 是第一公民，默认 `input_mode=direct`。
2. `Refine / 智能整理` 是可选能力，不应阻塞快速输入。
3. 保留轻量浮窗和逐字输入动画，但可靠完整输入优先于动画。
4. 普通软件不需要用户切换输入法，也不应要求日常以管理员身份运行语润。
5. 高权限目标软件通过独立输入助手兼容；助手不可用时必须回退普通路径。

## 4. 当前 PRE 最近一轮修改

最近一轮只针对“纠错窗口在 Cindy 中看不见、拖动位置不记忆”进行，文件只在 `Pre/`：

### 4.1 纠错热键立即冻结目标窗口

`Pre/src/main.py` 的纠错热键线程在触发瞬间记录前台窗口句柄，再将句柄交给 Tk 主线程。

原因：如果等 UI 队列稍后处理才读取前台窗口，Cindy、Chrome/Electron 等应用可能已经短暂失焦，导致读取选区和定位对象错误。

日志新增目标窗口信息：

```text
纠错目标窗口: hwnd=... title='...' class='...'
```

### 4.2 纠错窗口位置记忆

`Pre/src/config.py` 增加：

```python
"correction_window_position": None
```

用户拖动纠错窗口后，坐标写入 PRE 配置；下一次打开优先恢复该坐标。关闭、取消、确认和拖动防抖都会保存。

### 4.3 纠错窗口可见性定位

旧实现使用上一轮浮窗锚点，并把整个虚拟桌面当作边界。多显示器布局中，虚拟桌面允许负坐标，导致窗口可能被放到屏幕上方。

新实现：

1. 优先恢复用户上次位置，只要该位置仍落在任一显示器工作区。
2. 没有有效保存位置时，读取热键触发时的目标窗口矩形。
3. 使用目标窗口所在显示器的工作区，而不是整个虚拟桌面。
4. 最终强制把窗口限制在工作区内。
5. 显示后再次 `lift`、`topmost`、`focus_force`，避免窗口创建成功但被压在后面。

日志新增定位信息：

```text
纠错窗口定位: source=target_window work_area=(...) x=... y=... w=560 h=490
纠错窗口定位: source=saved work_area=(...) x=... y=... w=560 h=490
```

### 4.4 剪贴板读取逻辑

窗口先显示，再执行：

```text
备份原剪贴板 → 临时回到目标窗口 → Ctrl+C → 延迟读取 → 恢复剪贴板
```

剪贴板读取失败只影响“识别文本”自动填充，不应阻止纠错窗口出现；用户仍可以手动填写。

## 6. 如何运行和测试 PRE

先退出任务栏中的 Stable 或 PRE，避免两个全局热键监听器同时运行。

运行：

```text
D:\SynologyDrive\CODING\yurun\Pre\run_pre.bat
```

PRE 的命令行窗口不要立即关闭；如果启动失败，窗口最后几行是关键错误。

### 纠错窗口测试

1. 在 Cindy、ChatGPT、记事本各选中一段文字。
2. 按 `Ctrl + 反引号`。
3. 确认纠错窗口出现在当前显示器内。
4. 拖动窗口顶部到新位置。
5. 关闭窗口，再次按热键。
6. 确认它恢复到刚才的位置。
7. 检查 `%APPDATA%\Yurun-Pre\config.json` 是否出现：

```json
"correction_window_position": {
  "x": 1996,
  "y": 1280
}
```

### 日志位置

```text
%APPDATA%\Yurun-Pre\logs\yurun.log
```

重点检索：

```text
纠错热键触发
纠错窗口 UI 事件开始
纠错目标窗口
纠错窗口已显示
纠错窗口定位
纠错选中文本读取完成
纠错窗口位置已保存
```

### 语音输入回归测试

- 普通记事本：按住反引号说短句，松开后应输入。
- ChatGPT/Cindy：测试短句、长句、连续两句。
- WorkBuddy 等高权限程序：确认安装过 `YurunInputHelper.exe`，主程序不需要管理员身份。
- 检查浮窗位置、输入内容、动画是否在真实文字完成前平稳结束。

## 7. 下一位开发者的第一步

不要先重构，也不要先做 TSF。建议按以下顺序：

1. 关闭现有语润进程，运行 `Pre/run_pre.bat`。
2. 在 Cindy 和一个普通 Win32 程序中重复纠错窗口测试。
3. 检查日志里的 `work_area`、`source`、`x/y` 是否合理。
4. 如果仍有看不见的问题，先判断是：
   - 窗口没有创建；
   - 创建后坐标仍越界；
   - 被高权限窗口遮住；
   - 多显示器 DPI 坐标换算问题；
   - 纠错热键被目标程序拦截。
5. 只有拿到新的日志证据后才改代码。
6. 修复确认后，先由用户验收，再决定是否 Promotion 到 Stable。

Promotion 前必须：

- 给当前 Stable 打 tag 或完整备份；
- 记录修改文件和回滚点；
- 构建并测试安装包；
- 人工确认后才复制/合并到 `src/`；
- Promotion 完成后按用户要求清空 PRE，作为下一轮空白开发区；
- 不自动删除 `dist/`、备份目录或用户资料。

## 8. 明确暂停、禁止越界的方向

以下方向此前已经讨论过，但当前没有获得继续施工授权，或风险尚未接受：

### 8.1 TSF 输入法实验

`Pre/tsf_bridge/` 中存在阶段性实验资料，但 TSF 是宿主进程内加载的 COM DLL，不是普通后台 EXE。它涉及：

- x86/x64 双架构；
- Active TIP 归属和输入法切换；
- `ITfContext::RequestEditSession` 编辑锁；
- IPC、UIPI、管理员权限和宿主崩溃风险；
- 目标程序可能被 DLL 崩溃连带带崩。

当前决定：暂停，不得因为“想做得更像输入法”就直接启用或注册。

### 8.2 常驻麦克风与 pre-roll

尚未开始。优点是可以降低按键后的首帧等待，缺点是权限、隐私、资源占用和误触风险明显增加。当前快速输入已经可用，不应未经评估直接加入。

### 8.3 Partial 直接写入 / TSF 原生上屏

高风险、尚未开始。当前稳定策略是完整 Final 后可靠输入；Partial 直接上屏会带来回滚、重复字、宿主兼容和焦点丢失问题。

### 8.4 Personal Memory 自动学习

当前只允许用户主动确认“错误词 → 正确词”后学习；不得监控用户在其他软件中的键盘内容，不得把剪贴板当作自动学习来源。
