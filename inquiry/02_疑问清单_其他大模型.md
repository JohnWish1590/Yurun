# 语润（Yurun）听写润色延迟优化 —— 疑问清单

> 用途：向通用大模型逐项提问，获取技术判断。每条含【背景】【具体问题】【期望回答方向】。
> 前提：当前润色由在线大模型执行（方舟 DeepSeek-V4-Flash，TTFT≈1.07s，已关 thinking），但整体出字体验仍慢于预期。

---

## 疑问 1：本地规则能否替代在线模型完成听写润色？

- **背景**：Cindy 的润色 prompt 已获取，是一段指令文本，当前由在线模型执行。为消除在线延迟，希望评估「纯本地规则」方案。
- **具体问题**：将 prompt 中「机械可枚举」的部分（补标点、去除「嗯 / 呃 / 那个」等口头词、口述格式转写如「换行」→ 回车、数字与单位规整）用本地正则 + 词典实现，可达成多高的完成度？而语义级部分（结合上下文还原术语、判断自我修正、低置信度乱码兜底）是否**绝对无法**用规则复现？
- **期望回答方向**：给出「规则可覆盖 vs 必须模型」的明确边界清单（最好带示例），并评估纯规则方案在「中英混说 + 专业术语多」的真实场景下的可用度。

## 疑问 2：本地小模型在无 GPU 机器上的可行性

- **背景**：用户设备为 Intel NUC i5-1240P（无独立显卡，仅 CPU / 核显），希望本地跑小模型以避免在线延迟。
- **具体问题**：在该硬件上，用 Ollama 部署 qwen2.5-3b / 7b、phi-3-mini、gemma2-2b 等模型做听写润色，预期推理速度与质量如何？是否可能反而慢于在线方案（方舟 TTFT≈1s）？有无更适合端侧、且中文润色质量尚可的模型推荐？
- **期望回答方向**：基于 CPU 推理的量化模型速度估算、具体模型推荐、以及「本地 vs 在线」延迟的临界点判断。

## 疑问 3：在线模型润色感知延迟的优化手段

- **背景**：已迁方舟、关 thinking，TTFT≈1s，但整体出字仍慢，希望进一步压缩感知延迟。
- **具体问题**：除换端点、关 thinking 外，还有哪些手段降低「感知延迟」？例如：流式输出 + 边出边打字、本地先做机械预处理再发模型、预热 / 复用 HTTP 连接、更小更快的模型（如 deepseek-v3-lite）、本地缓存相似句等。
- **期望回答方向**：按「见效快 → 慢、成本低 → 高」排序的可行优化清单，标注每条预期收益与风险。

## 疑问 4：「松手即出原文、后台润色原位替换」的稳健实现

- **背景**：早期版本（v0.1.2）采用「松手先贴原文、后台润色完再原位替换」，出字最快；但因「替换时误删光标前文」被废弃，改为「长句等润色完才出」（v0.1.7 方案 B）。
- **具体问题**：如何用稳健方式实现「先出原文、后原地替换润色结果」而**不误删**用户已有文本？可行的锚定手段有哪些（基于选区快照、基于插入点 offset 记录、基于前后文唯一片段 diff、或 SendInput 记录已输入字符数）？各方案的边界条件与失败兜底是什么？
- **期望回答方向**：给出 1–2 种工程上可靠的「原位替换」实现方案（含伪代码级要点）与失败兜底策略。

## 疑问 5：出字速度瓶颈的量化拆解

- **背景**：用户主观「慢」，但不确定瓶颈究竟在哪一段。
- **具体问题**：一段典型语音听写（说完松手到最终文字落定）的时间通常分布在：① ASR 识别等待（必须等说完）② 网络往返 ③ 模型推理（TTFT + 生成）④ 逐字打字（SendInput Unicode）。在「中速说话、约 30 字句子、方舟 TTFT≈1s」的假设下，各段大致耗时占比？哪段最值得优化？逐字打字间隔（如每字 10–30ms）是否会成为新瓶颈？
- **期望回答方向**：给出各阶段典型耗时区间与排序，指出「投入产出比最高」的优化点。

## 疑问 6：混合方案（本地规则兜底 + 在线语义润色）的设计

- **背景**：纯本地质量差，纯在线有延迟，希望取折中。
- **具体问题**：能否设计「短句 / 简单句走本地规则秒出，长句 / 复杂句（含术语、中英混说、自我修正）才触发在线模型」的分流策略？判定启发式有哪些（句长、是否含英文术语、是否有口头词 / 修正信号、用户词典命中）？本地规则能否先做一遍格式化预处理，让在线模型只处理语义，从而进一步降延迟？
- **期望回答方向**：给出可落地的分流判定规则与「预处理 — 在线协作」流程，评估质量与速度的平衡点。

## 疑问 7：确认「纯本地 Cindy 级润色」是否真实存在

- **背景**：用户怀疑 Cindy 是纯本地润色所以快，想确认该路线是否真实可行。
- **具体问题**：从产品形态（Electron 应用、需联网、需账号 / API）与行业通行做法判断，Cindy 这类听写工具「完全不调用在线模型、纯本地规则或小模型完成 Cindy 级润色」的可能性有多大？若确实纯本地，技术路线最可能是哪种（端侧 LLM 如本地 GGUF / 规则引擎）？
- **期望回答方向**：基于行业常识给出可能性评估与最可能的技术路线，帮助判断是否值得投入「本地化」路线。
