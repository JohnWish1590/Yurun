# 语润开发过程：思考、尝试与反复

这份文档保留语润从方案讨论到正式发布的过程记录。它不是当前版本的操作手册，也不替代 `CHANGELOG.md`；这里重点记录当时为什么这样想、尝试过什么、哪些判断被实测推翻，以及最后留下了什么。

## 2026-08-29：先判断产品到底要解决什么

最初的产品目标很明确：语润是一个快速、高效、功能简单的 Windows 语音输入工具，用来补充键盘和现有输入法，而不是重新做一个输入法。

架构检查得出三个重要事实：

1. SAUC 已经提供真流式 ASR，服务端持续返回 Partial；当时的问题不是换 ASR，而是代码只保存最终文本，没有把 Partial 变成用户可见反馈。
2. 当前跨应用输入依靠 `SendInput`，稳定性和兼容性优先；真正的 inline preedit 需要 TSF，但这会显著扩大风险和维护面。
3. 个人词库只能建立在用户明确确认的纠错上，不能监听用户键盘或把偶然出现的词自动当成学习样本。

因此形成了第一条路线：保留 SAUC 和现有输入链路，先修正测量、释放可用反馈，再评估伪 Preedit，最后才考虑 TSF。没有因为“更像输入法”就立即重写输入层。

## 2026-08-29：对重构方案逐条采纳、修正和否决

外部方案提出了 Direct Mode、立即整段输入、焦点策略、常驻麦克风、VoiceSession、Personal Memory 和大目录重构等方向。逐条核对源码和历史日志后，做了以下取舍：

- **采纳**：快速直接输入作为默认范式；动画使用固定预算而不是随文本长度线性变慢；记住目标窗口而不是强行抢回焦点；显式纠错作为个人记忆的入口。
- **修正**：不直接砍掉逐字动画，而是给长文本设置自适应预算；先补全延迟测量，再判断 ASR、连接和输入哪个环节真正耗时。
- **否决或后置**：暂不做 `src/` 十目录大搬家、立即整段落入、常驻麦克风/pre-roll、TSF 和自动监听键盘学习。这些方向并非永远不做，而是当时没有足够证据证明收益能够覆盖风险。

后续实测发现，用户感知的 P0 延迟中动画约占 92%。这改变了优先级：先让短句保留手感、长句封顶加速，比先追逐“首个 Partial 必须小于 500ms”更直接有效。

## 2026-08-29～08-30：Pre 隔离方案与第一次反复

为了不影响正式版，曾设计过独立的 `Pre/` 预览区：代码、配置、日志、词库、PID、托盘标识和启动入口全部隔离，Stable 与 Pre 不同时运行，Pre 失败时可以直接退出而不影响 Stable。

这套方案解决的是“如何安全试验”，不是产品功能本身。执行过程中，Phase 0 的低风险改动逐步验证完成并提升到正式代码；之后正式版成为唯一主线，Pre 不再作为持续开发目录。

保留下来的经验是：涉及输入、权限、全局热键和用户数据时，先隔离、单项验证、可回退，再提升到正式版；不要把 Preview 自动同步回 Stable。

## 2026-08-30～09-04：从基础体验到正式功能

按上述取舍推进了 1.3.x：

- 默认快速输入与自适应输入动画落地；
- 会话隔离、最终结果保护、浮窗定位和输入失败可见化逐步补齐；
- 设置、热键、纠错窗口、图标和高权限输入兼容进入正式路径；
- 个人记忆只接受用户明确确认的“错词 → 正确词”。

这些版本中反复出现的共同原则是：每次只改一个行为边界，先做语法、模拟和真机验证，再继续下一项；没有为了目录漂亮而重写已稳定的模块。

## 2026-09-20：1.4.0 正式纳入纠错与输入控制

Preview 阶段验证的热键自定义、录音/纠错热键分离、选中文字纠错、管理员权限软件兼容和窗口定位改进进入正式版，形成 1.4.0。

同时明确暂不纳入：TSF 输入法、常驻麦克风、pre-roll、Partial 原生上屏和自动键盘学习。它们仍是未来探索方向，不是当前用户依赖的稳定功能。

## 2026-09-20～09-21：安装、崩溃与剪贴板的连续修复

1. **1.4.1：先解决升级本身。** 旧版高权限输入助手是无界面常驻进程，Restart Manager 无法可靠结束它，安装时会出现“无法自动关闭所有应用程序”。安装器改为在 `PrepareToInstall` 中显式结束主程序和助手，卸载路径也采用同样的保险。
2. **1.4.2：补齐输入和持久化边界。** 长文本批量输入、UTF-16 代理项、助手断线、剪贴板事务、配置/词典原子保存、单实例身份校验和 UI Automation 打包一起完成，并增加回归测试。
3. **1.4.3：处理纠错窗口崩溃。** 日志和 Windows 崩溃报告指向 `0xc0000374` 堆损坏。根因是把并非 HGLOBAL 的剪贴板句柄按原始内存恢复。修复为只处理明确安全的格式，跳过位图和私有格式。
4. **1.4.4：修复过度收紧带来的反效果。** 1.4.3 的安全过滤漏掉了实际选区流程中的 `CF_DIB/CF_DIBV5`，于是纠错窗口不再自动读到文本。1.4.4 将这两种安全格式加入快照范围，同时继续跳过 `CF_BITMAP` 和应用私有格式；安装器还显式绑定快捷方式图标，避免错误或旧缓存图标。

## 当前留下的工程结论

- 正式版只有一条主线，发布给普通用户的是一个安装包，不要求用户理解内部助手和构建产物。
- 版本号每次重新打包都递增，`src/logger.py` 与 `installer/yurun_setup.iss` 必须一致。
- GitHub Release 只发布安装包；`build/`、`dist/` 和 Python 缓存属于本地生成物，不进入源码仓库。
- 重大输入层变化必须单项实施、实际验证，并保留可回退的 Git 标签或发布记录。
- 未来若继续向“输入法”方向发展，应先从可测量的 Partial/反馈体验开始，再决定是否进入伪 Preedit 或 TSF；不能因为概念先进就跳过稳定性验证。

精确的每版文件、验证结果和行为变化见 [`CHANGELOG.md`](../CHANGELOG.md)。
