# 语润 Yurun

## 按住说话，松手成字。

**在 Windows 的任何地方。**

语润（Yurun）是一个 Windows 全局语音输入工具。

把光标放在微信、浏览器、ChatGPT、Codex、Word、编辑器或其他任何可以输入文字的地方，按住一个键开始说话，松开后，文字就会直接进入当前输入框。

不需要切换窗口。
不需要打开录音界面。
不需要复制粘贴。
也不要求你改变原来的输入法。

> **你能打字的地方，都可以直接说。**

---

> **当前版本：v1.3.0**
>
> 默认快速直接输入；可按需切换至 AI 智能整理。支持实时识别浮窗、全局热键、用户词库、本地轻清洗与系统托盘常驻；长文本会自动加速输入动画。

---

## 为什么做语润

电脑已经有很多语音识别工具。

Windows 有语音输入，输入法有语音功能，很多 AI 应用也自带麦克风。

所以语润并不想再做一个“语音识别软件”。

它真正想解决的是另一件事：

> **当你已经知道自己想说什么时，怎样用最少的动作，把这些话送进电脑。**

尤其进入 AI 时代以后，我们开始越来越频繁地向 ChatGPT、Claude、Codex、Cursor，以及各种 AI 工具输入大量自然语言。

很多时候，限制交流速度的已经不是 AI。

而是键盘。

人的说话速度远远快于打字速度。

语润希望把语音变成一种像键盘一样自然的输入方式：

```text
光标放好
↓
按住 `
↓
说话
↓
松开
↓
文字进入当前输入框
```

仅此而已。

---

# 它不是输入法

语润不会替代微软拼音、搜狗、微信输入法或其他任何输入法。

你可以继续使用自己习惯的一切。

语润只是运行在它们之上的一层：

> **Universal Voice Input · 全局语音输入层**

微信里可以说。

ChatGPT 里可以说。

Codex 里可以说。

浏览器搜索框可以说。

Word 可以说。

编辑器可以说。

只要当前有一个可以输入文字的光标，语润就在那里。

最终希望形成一种简单的肌肉记忆：

> **想输入一段话 → 按住 → 说。**

---

# 核心体验

## ① 快速直接输入

这是语润最核心的模式。

按住默认热键 `` ` `` 开始说话，松开后识别结果直接进入当前输入框。

不经过大模型重新生成，不等待 AI 润色。

本地只进行少量低风险清洗，例如：

* 去除部分「呃」「嗯」「额」等口头停顿
* 清理部分不必要的短句句末标点
* 保留原本的说话方式和语义
* 保留「这个」「那个」「然后」「其实」「就是」等可能具有真实语义的词
* 保留「啊」「呀」「吧」等正常语气

原则很简单：

> **尽可能保持“我说什么，就写什么”。**

对于 ChatGPT Prompt、即时聊天、搜索、代码指令、投资讨论以及大量日常输入，这通常已经足够。

---

## ② 边说边看见

语音输入不应该像把一句话扔进黑盒。

录音过程中，语润会在当前光标附近显示实时识别结果。

你可以边说边看到文字出现。

松开按键后，最终文字进入当前输入框。

整个过程尽量停留在你正在工作的地方，而不是把注意力拉到另一个窗口。

### 实时浮窗

* 跟随当前输入位置出现
* 识别结果边说边显示
* 固定左缘，向右 / 向下自然生长
* 自动根据背景亮暗调整显示效果

### 悬浮 Pill

按下热键时立即出现轻量状态提示：

```text
● 正在录音
```

需要 AI 处理时：

```text
⟳ 正在润色
```

没有大窗口。

没有工作流中断。

# 越用越懂你

通用语音识别可以认识普通话。

但真正长期使用以后，人最容易被识别错误的往往不是普通词，而是：

* 人名
* 公司名
* 产品名
* 专业术语
* 英文缩写
* 项目名称
* 自己经常使用的特殊表达

例如：

```text
MiniMax
Codex
SAUC
CDMO
license-out
Kingsoft
某个同事的姓名
某个内部项目名称
```

因此语润正在建立自己的 **个人词库系统**。

当一个词被纠正后，语润可以记录：

```text
正确写法：changelog

曾经识别成：
天气log
天气 Log

累计纠正次数：3
```

这些信息可以进一步用于：

1. **ASR 热词**

   尽可能让语音识别从源头就认识这个词。

2. **本地纠错**

   在快速直接输入模式下，对已经确定的错误进行低延迟修正。

3. **AI 词典**

   在使用润色模式时，告诉大模型哪些名字、术语和表达应该被保留。

目标不是让语润成为“最聪明的 AI”。

而是：

> **让它越来越懂使用它的这个人。**

---

# AI 是能力，不是前提

语润最初诞生于“语音转写 + AI 润色”。

这个能力仍然保留。

但现在的产品原则变得更加明确：

> **语音输入是核心。AI 是需要时才调用的增强能力。**

很多时候，你并不需要 AI 改写自己的话。

例如向 ChatGPT 输入：

```text
你把金蝶今年这几个业务拆开看一下，
尤其帮我看看订阅收入的变化。
```

这本身已经是一个很好的 Prompt。

这种情况下：

**快速说出来，比重新润色一次更重要。**

# 可选：轻润色

当你确实需要把口语整理成更完整的书面表达时，可以打开「润色」。

例如原始口语：

```text
嗯这个我觉得吧今天这个财报其实有几个问题
第一个就是这个利润质量可能没看起来那么好
然后第二个就是现金流
```

可以整理成：

```text
我觉得今天这份财报主要有两个问题。

第一，利润质量可能没有表面看起来那么好；
第二，需要进一步关注现金流表现。
```

轻润色主要负责：

* 删除明显口水词
* 整理重复表达
* 修复断裂句子
* 调整基本标点
* 中英文混杂修正
* 尽量保留原始语气和意思

同时设有发散保护。

如果模型输出明显偏离原文，会优先回退到原始内容。

# 两种输入方式

## 快速输入

```text
语音
 ↓
实时识别
 ↓
少量本地清洗
 ↓
当前输入框
```

特点：

**快 / 直接 / 可预测**

适合：

* ChatGPT / Claude Prompt
* Codex / Cursor 指令
* 微信聊天
* 搜索
* 日常短文本
* 高频连续输入

---

## AI 轻润色

```text
语音
 ↓
实时识别
 ↓
AI 轻度整理
 ↓
当前输入框
```

特点：

**更完整 / 更书面 / 更适合长段表达**

适合：

* 邮件
* 长段说明
* 工作文字
* 内容创作
* 需要去除大量口语重复的场景

两种模式都遵守同一个原则：

> **说话 → 文字直接进入当前工作位置。**

# 为什么不是直接使用 Win + H？

如果 Windows 自带语音输入已经完全满足你的需求，那么继续使用它就很好。

语润并不是为了证明自己的 ASR 比系统更强。

它更关注另外几个问题。

## 一致

无论当前在微信、浏览器、AI、Word 还是编辑器，都使用同一套操作。

## 低摩擦

不寻找麦克风按钮。

不切换窗口。

不改变当前工作状态。

## 可控

需要原话就直接输入。

需要整理时再调用 AI。

## 个性化

逐渐积累属于自己的名字、术语和纠错记录。

## 开放

语音识别服务和 AI 模型并不绑定某一家厂商。

# 一个非常适合语润的场景：和 AI 说话

AI 正在改变电脑输入的结构。

以前，一天可能只需要：

* 回复一些微信
* 写几封邮件
* 搜索一些关键词

现在越来越多的人每天需要给 AI 输入大量自然语言：

```text
解释这个问题
```

```text
把这里重构一下
```

```text
比较这两家公司
```

```text
继续分析刚才那个结论
```

```text
帮我看看这段代码为什么慢
```

几十字、几百字甚至几千字的 Prompt 开始成为日常。

这时候：

> **键盘可能正在成为人与 AI 沟通的带宽瓶颈。**

语润希望成为这种工作方式里的：

## Voice Keyboard for the AI Era

**AI 时代的语音键盘。**

如果你经常出现：

那语润可能适合你。

# 使用方式

## 默认：按住说话

把光标放到任意输入框。

按住键盘左上方、Tab 上方的：

```text
`
```

开始说话。

松开。

文字进入当前输入框。

---

## 单击切换

也可以在设置中改成：

```text
按一下 → 开始录音
再按一下 → 结束录音
```

适合较长时间连续表达。

# 安装

## 方式 A：直接运行 EXE

前往 GitHub Releases：

https://github.com/JohnWish1590/Yurun/releases

下载最新版本。

无需安装 Python。

运行后，语润会常驻系统托盘。

首次启动时会在：

```text
%APPDATA%\Yurun\
```

创建本地配置。

---

## 方式 B：源码运行

建议 Python 3.12。

```powershell
pip install -r requirements.txt
python src/main.py
```

也可以使用项目中的：

```text
run_yurun.bat
```

---

## 自行打包为独立 EXE

```powershell
pyinstaller Yurun.spec --noconfirm
```

使用 Inno Setup 可进一步生成安装包。

# 配置

## 语音识别

当前默认使用火山引擎 SAUC 流式语音识别。

需要填写对应的语音识别 Key。

语音会边录制边通过 WebSocket 流式发送，因此实时结果可以直接显示在浮窗中。

---

## AI 润色

AI 润色完全可选。

支持 OpenAI Compatible API，例如：

* 火山方舟
* DeepSeek
* 阿里百炼
* 其他兼容 OpenAI API 格式的模型服务

配置：

```text
API Key
API Base
Model
```

如果不配置 AI：

> **语润仍然可以作为快速语音输入工具使用。**

---

# 本地优先

语润目前没有自己的云端账号系统。

开发者服务器不会收集你的：

* 录音
* 转写内容
* API Key
* 用户词库
* 输入历史

配置和用户数据默认保存在本机。

网络数据只发送给你自己配置的：

* ASR 服务商
* AI 模型服务商

详细说明请阅读：

[PRIVACY.md](PRIVACY.md)

这也意味着语润天然支持一种方式：

> **Bring Your Own Key · BYOK**

你选择自己的服务。

语润只负责完成输入。

# 产品原则

语润还很年轻。

但有几条原则希望长期保持。

## 1. 主路径必须足够短

```text
按下 → 说话 → 松开 → 出字
```

任何新功能都不应该轻易破坏这条路径。

## 2. 快比炫技重要

高频输入工具首先应该可靠、快速、可预测。

## 3. AI 应该安静

需要 AI 时，它应该帮忙。

不需要时，它不应该挡在用户和文字之间。

## 4. 用户拥有自己的数据

个人词库、配置和习惯属于用户。

## 5. 越用越懂你

真正值得长期积累的不是某一个模型，而是：

> **这个输入工具越来越了解自己的主人。**

---

# 已知限制

* 当前仅支持 Windows。
* 依赖 Win32 全局热键及输入焦点能力。
* 当前默认 ASR 为火山 SAUC。
* ASR 的实时 partial 结果偶尔可能出现重复或抖动，最终结果通常会在服务端收敛。
* AI 润色速度取决于所选择的大模型服务，与 ASR 速度不是同一件事。
* 快速输入模式只做低风险本地清洗，不进行复杂语义改写。
